## Перед началом работы

1. **Проверьте существующие Issues** — возможно, ваша проблема уже обсуждается.
2. **Создайте Issue** перед началом большой работы — обсудите подход.
3. **Форкните репозиторий** и создайте отдельную ветку:

   ```bash
   git checkout -b feature/new-example
   ```

4. **Установите зависимости** (см. `README.md`).

---

## Требования к новым решениям

Каждый новый Notebook должен:

### 1. Иметь понятное название

Имя файла должно следовать соглашению об именовании:

```
NN_<topic>.ipynb
```

Например: `12_vector_calculus.ipynb`, `13_gradient_descent.ipynb`.

### 2. Содержать формулировку задачи своими словами

- ❌ **Запрещено** копировать большие фрагменты текста из книги.
- ❌ **Запрещено** копировать иллюстрации или сканы страниц.
- ✅ Условие задачи пересказывается **кратко и своими словами**.
- ✅ При необходимости даётся **ссылка** на раздел книги.

### 3. Иметь математическое объяснение

- Объясните, **какие понятия, формулы и методы** используются.
- Приведите **пошаговое математическое решение**.
- Используйте LaTeX для формул в markdown-ячейках.

### 4. Содержать реализацию на Python

- Код должен быть **аккуратно оформленным и понятным**.
- Импорты собираются в первой кодовой ячейке.
- Используются осмысленные имена переменных.
- Код снабжается комментариями в сложных местах.

### 5. Содержать проверку результата

- Численная проверка,
- визуализация,
- или альтернативный способ проверки (например, через SymPy или другую библиотеку).

### 6. Завершаться итоговым выводом

- Краткий итог.
- Указание, **какие математические идеи** были продемонстрированы.
- Связь с практическими задачами машинного обучения.

## Единая структура Notebook

Все Notebook'и в репозитории следуют единой структуре:

```markdown
# Пример NN. Название

## Тема

## Условие

## Математическая идея

## Решение

## Реализация на Python

## Дополнительный пример

## Проверка результата

## Вывод
```

Пожалуйста, следуйте этой структуре при создании новых Notebook.

## Требования к коду

### Читаемость

- Используйте осмысленные имена переменных и функций.
- Соблюдайте PEP 8 (можно использовать `flake8` или `black`).
- Добавляйте комментарии в сложных местах.

### Воспроизводимость

- ✅ Notebook должен **выполняться последовательно от начала до конца** без ошибок.
- ✅ Перед отправкой Pull Request перезапустите все ячейки.
- ✅ Сохраните Notebook с результатами выполнения ячеек.

### Импорты

- Все импорты должны быть в **первой кодовой ячейке** Notebook.
- Если вы используете новую библиотеку, добавьте её в `requirements.txt` с пояснением.

---

## Зависимости

### Когда добавлять новую зависимость

- Только если она **действительно необходима** для решения задачи.
- Если аналогичной функциональности нет в уже подключённых библиотеках.
- Если библиотека поддерживается и имеет открытую лицензию.

### Как добавить зависимость

1. Добавьте библиотеку в `requirements.txt` с указанием минимальной версии.
2. Добавьте комментарий с пояснением, **зачем** нужна библиотека.

---

## Правила работы с материалами книги

⚠️ **Это очень важно.** При добавлении материалов из книги:

- ❌ **Нельзя** копировать большие фрагменты текста из книги.
- ❌ **Нельзя** копировать иллюстрации, графики, диаграммы или сканы страниц.
- ❌ **Нельзя** копировать формулировки задач дословно.
- ✅ Условия задач **пересказываются своими словами**.
- ✅ При необходимости даётся **ссылка** на раздел книги.
- ✅ Решения пишутся **самостоятельно** — это авторские материалы репозитория.

Нарушение этого правила приведёт к отклонению Pull Request.

## Процесс отправки Pull Request

1. **Форкните** репозиторий.
2. **Создайте ветку** с описательным именем:

   ```bash
   git checkout -b feature/example-12-vector-calculus
   ```

3. **Внесите изменения**, следуя правилам выше.
4. **Проверьте**, что Notebook выполняется от начала до конца:

   ```bash
   jupyter nbconvert --to notebook --execute notebooks/12_vector_calculus.ipynb
   ```

5. **Запустите тесты** (если они есть):

   ```bash
   pytest tests/
   ```

6. **Сделайте коммит** с понятным сообщением:

   ```bash
   git commit -m "add: добавлен пример 12 по теме векторного исчисления"
   ```

7. **Отправьте изменения** и **откройте Pull Request**.

---

## Стиль коммитов

Рекомендуется придерживаться формата:

```
<тип>: <краткое описание>
```

**Типы коммитов:**

- `add` — добавлен новый пример или функция
- `fix` — исправлена ошибка
- `docs` — изменения в документации
- `refactor` — рефакторинг кода
- `test` — добавлены или исправлены тесты
- `chore` — обслуживание проекта
